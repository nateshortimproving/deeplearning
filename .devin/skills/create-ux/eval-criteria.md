[Definitions]
• User Personas: Who uses the feature — their role, goals, and pain points.
• User Flows: Step-by-step user/system interactions, each with a decision point and error risk.
• Key Interactions: Important UI patterns and their expected behavior.
• Design Considerations: Accessibility, responsiveness, and usability requirements.
• Error States: What can go wrong, what the user sees, and how they recover.

EC 1: User Personas, User Flows, Key Interactions, Design Considerations, and Error States sections are required. Fail if any is missing or empty.
EC 2: There must be at least two Personas, each with a Role, Goals, and Pain Points entry.
EC 3: There must be at least two User Flows, each with at least three numbered steps plus a Decision Point and an Error Risk entry.
EC 4: Error States must be a table with at least two rows, each having Scenario, User Sees, and Recovery Action filled.
EC 5: Design Considerations must address both accessibility AND responsiveness (or a screen-size/mobile equivalent).
