[Definitions]
• Overview: 1-2 paragraph summary of the architectural approach — the "why" of the design.
• Components: Named units of the system, each with Responsibility, Interfaces, and Dependencies.
• Data Flow: How data moves through the system between components.
• Key Technical Decisions: Significant technology/design choices, each with the chosen option and rationale.
• Constraints: Technical and non-functional limits the design must respect.

EC 1: Overview, Components, Data Flow, Key Technical Decisions, and Constraints sections are required.
EC 2: There must be at least three Components, each with a Responsibility.
EC 3: The Key Technical Decisions section must contain a table with at least two decision rows, each having a Decision, a Choice, and a Rationale.
EC 4: The Constraints section must list at least two items.
EC 5: Every named component must appear in the Data Flow narrative or diagram reference (no orphan components).
