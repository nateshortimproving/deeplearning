# Program Completion Rubric
*Administered at Week 12 — joint assessment by Embedded Engineer and Trainer*

---

## Purpose

This rubric is the formal completion assessment for Deep Learning Program (DLP) participants. It is completed jointly by the Embedded Engineer and Trainer, informed by the participant's AI Adoption Maturity Assessment results (administered at Week 1, Week 7, and Week 12) and the participant's committed artifacts.

**Completion = demonstrated DLP Completion behavior across all four Evaluation Criteria. Knowledge alone does not satisfy any criterion.**

DLP Completion requires these four tangible outcomes:
1. Iterative refinement of skills and adversarial agents
2. Deliberate usage of Python evaluation scripts with LLM judges to codify performance against Evaluation Criteria (EC)
3. At least 1 core human workflow step developed to 95%+ accuracy
4. Changed human behavior to use high-reliability skills in place of manual work

These outcomes are assessed through the four behavioral Evaluation Criteria below (Craft, Evaluate, Iterate, Adopt).

---

## Rubric

### Criterion A: Craft
*Can the participant build skills and adversarial agents for their own real work?*

| Level | Description |
|-------|-------------|
| **Not Met** | Has not committed a working skill or adversarial agent relevant to their actual job |
| **Partial** | Has committed at least one artifact but it was built with heavy Embedded Engineer involvement and the participant could not reproduce it independently |
| **Met** | Has committed at least one skill with `disable-model-invocation: true` and at least one of: a skill with model invocation enabled or an adversarial agent; can explain each; built at least one primarily independently |
| **Exceeded** | Has committed multiple artifacts across different workflow areas; team members are using their artifacts; participant has helped at least one colleague build something |

### Criterion B: Evaluate
*Does the participant use Python evaluation scripts with LLM judges as a standard practice?*

| Level | Description |
|-------|-------------|
| **Not Met** | Has not built or used a Python evaluation script with an LLM judge; cannot describe what one is |
| **Partial** | Has built an evaluation script but it has vague Evaluation Criteria (EC); has run it fewer than 3 times; results are not documented |
| **Met** | Has a working Python evaluation script with an LLM judge, with specific EC; has run it across 3+ iterations with documented hypotheses and results; can interpret the results |
| **Exceeded** | Applies evaluation thinking to new skills as a default; has taught another team member to use an evaluation script; is building evaluation into team practice |

### Criterion C: Iterate
*Does the participant improve skills and adversarial agents based on evaluation evidence?*

| Level | Description |
|-------|-------------|
| **Not Met** | Does not revisit skills after first use; treats initial output as final |
| **Partial** | Has done some iteration but without documented hypotheses; changes are intuition-driven, not evidence-driven |
| **Met** | Has at least one skill with 3+ documented improvement cycles against its Evaluation Criteria (EC); can articulate what changed, why, and what the evaluation script showed |
| **Exceeded** | Iteration is a habit; participant can describe a recurring pattern in what causes skills to degrade or improve; is applying this to new artifacts proactively |

### Criterion D: Adopt
*Has the participant actually changed their default behavior?*

| Level | Description |
|-------|-------------|
| **Not Met** | Still works the same way as at program start; AI tools are used occasionally but are not integrated into normal work |
| **Partial** | Has changed behavior in specific sessions or when prompted; reverts to old behavior under time pressure or when the Embedded Engineer isn't watching |
| **Met** | At least one real workflow task is now done differently as the *default*; participant would notice the loss of their AI-assisted approach; behavior persists without Embedded Engineer presence |
| **Exceeded** | Multiple workflow areas have changed; participant has influenced at least one colleague's behavior; AI assistance is now a load-bearing part of how they work |
