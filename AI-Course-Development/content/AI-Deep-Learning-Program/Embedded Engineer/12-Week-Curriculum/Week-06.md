## Embedded Engineer Focus (Testing Team)

- **Day 4:** Cross-team chain review. Walk through the full chain with representatives from all three teams: epics-and-stories → plan-story → implement-story → review-implementation. Each step's output evaluated against its EC. Use real stories from the sprint — the workspace taught the skills, the real codebase is where they should all be working by now. This is the Loop 1 capstone moment.
- **Day 5:** Loop 1 retrospective with the full group (all three teams if possible). What worked across the full chain? What would you change? What are you going to do differently in Loop 2?

**Key Embedded Engineer priority this week:** Close the loop on Loop 1. Ensure every participant has a complete, committed skill with EC and a load-bearing audit — built in the workspace and transferred to the real codebase. The retrospective should make the full SDLC skeleton pipeline visible and celebrate what's been built.

## Embedded Engineer Coaching Notes

- The Embedded Engineer does NOT introduce Python evaluation this week. Session 4 is where participants first encounter Python evaluation scripts and LLM judges. The approach is fully AI-coded — participants have the AI write the evaluation scripts for them. No Python prerequisite. The models carry the coding load.
- The Loop 1 retrospective is important for building cross-team awareness of the full chain. Make the chain visible: developers often don't know what the Product team has been building; the Testing team hasn't always seen the Plan → Code output.
- At the end of Week 6, every participant should be able to answer: "What is one thing you do differently now than you did in Week 1?" If they can't, Loop 2 needs to address the gap.
- The Embedded Engineer should do their own honest assessment: which participants are genuinely on track for DLP Completion, which are struggling, and what's the specific blocker? This shapes how they approach Loop 2.
- Frame Loop 2 for participants: "Loop 1 gave you the SDLC skeleton pipeline. Loop 2 is about making the evaluation of those skills systematic — Python evaluations, adversarial agents, and custom harnesses."
- **Transfer model note:** By end of Week 6, every skill should have been transferred from the workspace to the real codebase. The workspace is where the skills were built; the real codebase is where they should be producing value. If any team is still only running skills on workspace sample stories, that's a gap to close before Loop 2. The retrospective should surface this: "Which skills are you using on real work? Which are still workspace-only?"
